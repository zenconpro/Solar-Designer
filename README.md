## โครงสร้างไฟล์

| ไฟล์ / โฟลเดอร์ | คืออะไร |
|---|---|
| `index.html` | ตัวแอปทั้งหมด (หน้าตา + สูตรคำนวณ) |
| `data/rates.js` | อัตราค่าไฟ Ft ภาษี เกณฑ์ราชการ ราคาระบบ — **แก้ที่นี่ที่เดียว** |
| `scripts/build.mjs` | ตรวจความถูกต้อง แล้วรวมเป็นไฟล์เดียว → `dist/index.html` |
| `tests/` | ชุดทดสอบอัตโนมัติ + ค่าอ้างอิง (`golden.json`) |
| `docs/FORMULAS.md` | อธิบายสูตรทุกขั้น พร้อมตัวอย่างบ้าน SPECTRA |
| `vercel.json` | บอก Vercel ให้รัน build แล้วเอา `dist/` ขึ้นเว็บ |

เทียบกับงานก่อสร้าง: GitHub = ห้องเก็บแบบ (1 commit = 1 rev.) · Vercel = ผู้รับเหมาที่สร้างตามแบบล่าสุดให้อัตโนมัติ · ชุดทดสอบ = การทดสอบก่อนส่งมอบ

## ขึ้นเว็บทำงานอย่างไร

1. แก้ไฟล์ใน GitHub (branch `main`)
2. Vercel เห็นการเปลี่ยนแปลง → รัน `npm run build`
3. build ตรวจ `data/rates.js` และไวยากรณ์โค้ด
   - ผ่าน → เว็บจริงเปลี่ยนภายใน ~1 นาที
   - ไม่ผ่าน → **เว็บเดิมยังใช้งานได้ตามปกติ** (Vercel ไม่เปลี่ยนเว็บ)

## ทำงานแบบปลอดภัย: branch → preview → merge

เหมือนทำ mock-up ก่อนเทจริง — แก้บนสำเนา ดูผลบนลิงก์ชั่วคราว แล้วค่อยรวมเข้าเว็บจริง

1. ใน GitHub เปิดไฟล์ที่จะแก้ → กดรูปดินสอ (Edit)
2. แก้เสร็จ กด **Commit changes…** → เลือก **Create a new branch for this commit and start a pull request** → ตั้งชื่อ เช่น `rates-jan-2570`
3. กด **Create pull request**
4. รอ ~1 นาที Vercel จะสร้าง **Preview** (ลิงก์ชั่วคราว) — ดูได้ที่หน้า Pull request หรือใน Vercel › Deployments
   (ลิงก์ Preview อาจต้องล็อกอิน Vercel ก่อนเปิด)

5. เปิดลิงก์ Preview ตรวจตัวเลข ถ้าถูกต้อง → กลับไปที่ Pull request กด **Merge pull request** → เว็บจริงเปลี่ยน
6. ถ้าไม่ถูกต้อง → กด **Close pull request** เว็บจริงไม่ถูกแตะเลย

อ้างอิง: [Vercel · Environments / Preview](https://vercel.com/docs/deployments/environments)

## อัปเดตอัตราค่าไฟ (เช่น Ft งวดใหม่)

กกพ. ปรับ Ft ทุก 4 เดือน (ม.ค. / พ.ค. / ก.ย.) — แนะนำตรวจทุกรอบ

1. เปิด `data/rates.js` → Edit
2. แก้ตัวเลขที่เปลี่ยน + `updated` (ค.ศ.) + `updatedTH` + ลิงก์แหล่งอ้างอิงในบรรทัด `src:`
3. ข้อควรระวังในการพิมพ์
   - ตัวเลขห้ามมีจุลภาค: `200000` ไม่ใช่ `200,000`
   - ตัวเลขห้ามมีเครื่องหมายคำพูด: `0.1623` ไม่ใช่ `"0.1623"`
   - ถ้าพิมพ์ผิด build จะแจ้งว่าผิดบรรทัดไหน และเว็บเดิมยังใช้งานได้
4. Commit ผ่าน branch → ตรวจ Preview → Merge (หัวข้อด้านบน)
5. ตรวจเว็บจริง: หน้าตั้งค่า › ค่าไฟ ต้องขึ้น "อัตรา ณ …" วันที่ใหม่

**ผลต่อบ้านที่บันทึกไว้แล้ว**

- ขั้นบันได / TOU / ภาษี / เกณฑ์ → ใช้ค่าใหม่ทันทีทุกหลัง
- Ft / ราคาขายคืน / ราคาระบบ → เป็นค่าของแต่ละหลัง บ้านเก่าต้องแก้ช่อง Ft ในหน้าตั้งค่าเอง (หรือกด "คืนค่าเริ่มต้น")

## ย้อนเวอร์ชัน (ถ้าขึ้นเว็บแล้วมีปัญหา)

**เร็วที่สุด (ไม่ต้องแก้โค้ด)** — Vercel › Project › การ์ด Production Deployment → **Instant Rollback** → เลือกเวอร์ชันก่อนหน้า → Confirm

- แพ็กเกจฟรี (Hobby) ย้อนได้ 1 เวอร์ชันก่อนหน้าเท่านั้น
- ⚠ หลังย้อนแล้ว Vercel จะ **หยุดเอาการ push ใหม่ขึ้นเว็บจริง** จนกว่าจะกด **Undo Rollback** (เมื่อแก้ปัญหาเสร็จ)
- อ้างอิง: [Vercel · Instant Rollback](https://vercel.com/docs/instant-rollback)

**ถาวร** — GitHub › Commits → เปิด commit ที่มีปัญหา → แก้กลับ หรือให้ Claude ช่วยทำ revert แล้ว push ใหม่

## ชุดทดสอบ (สำหรับผู้พัฒนา)

ต้องมี Node.js 18 ขึ้นไป

```bash
npm run build
cd tests
npm install
npx playwright install chromium
npm test
```

ตรวจ 3 กลุ่ม

- **ก. ผลลัพธ์ 16 กรณี** (SPECTRA 3 วิธี + แบต + TOU + ขายคืน + ภาษี + แม่แบบอื่น) ต้องตรงค่าอ้างอิงทุกตัวอักษร
- **ข. สูตร 28 ข้อ** เทียบการคำนวณมือ (ตรงกับป้าย [✓] ใน `docs/FORMULAS.md`)
- **ค. หน้าเว็บ** ไม่มี error · ไม่ล้นแนวนอน (จอคอมและมือถือ) · หน้าตั้งค่าไม่ต้องเลื่อน

เมื่อ **ตั้งใจ** เปลี่ยนสูตร อัตรา หรือข้อความ → `npm test` จะแสดง "เดิม / ใหม่" ให้ตรวจ
ถ้าถูกต้องแล้ว → `npm run update` เพื่อบันทึกค่าอ้างอิงใหม่ แล้ว commit `tests/golden.json` ไปด้วย

ตรวจสูตรบนเว็บจริงได้เอง: เปิด `https://honour-solar.vercel.app/?debug=1` → F12 → Console →
`console.table(HS_DEBUG.formulaChecks())`

## ข้อมูลบ้านเก็บที่ไหน

- เก็บในเบราว์เซอร์ของเครื่องที่ใช้ (localStorage) — ไม่ได้ส่งขึ้นเซิร์ฟเวอร์
- ล้างข้อมูลเบราว์เซอร์ = ข้อมูลหาย → ใช้ปุ่ม **สำรองทุกหลังเป็นไฟล์** เป็นประจำ
- ย้ายเครื่อง: สำรองเป็นไฟล์ แล้ว **เปิดจากไฟล์สำรอง** ที่เครื่องใหม่ หรือใช้ **แชร์ลิงก์**
